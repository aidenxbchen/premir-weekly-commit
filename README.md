# PREMIR 周承诺

飞书自建应用：把"模块周里程碑 + 个人周承诺 + 全员评级"这套流程，从多维表格的原始表格界面，封装成卡片式表单，嵌在飞书客户端里免登录使用。桌面宽屏布局，左侧导航 + 右上角周次切换。

底层数据仍然是团队现有的多维表格（模块周里程碑表 + 全员评级表 + 每模块一张周承诺表），这个应用只是读写它，**不新建表**，也没有自己的数据库——飞书 Bitable 就是唯一数据源，本地只维护一份只读缓存加速页面加载。

评级徽章统一用"币"的视觉（金 = A、橙 = B+、淡蓝 = B、红 = C），不是文字方块；哪里出现评级，哪里就是这套配色。

## 功能

左侧六个页面（管理员额外多一个）：

- **各模块周里程碑**：4 个结构模块（洗净/烘干/熨烫/净水，不含软件组，见下方说明）并排卡片展示，不需要点开。内容包括里程碑描述、B/B+ 验收标准（负责人或管理员可编辑，编号格式的验收标准会自动拆成独立可勾选行）、负责人历史评级徽章，以及"周末评级"/"周一评级"两档独立评分——两档都是一次性锁定，选等级 + 填备注（选填）+ 确认提交后前后端都不允许二次修改。
- **全员评级表**：只读排行榜。每人一张卡片，展示头像姓名、固定 8 周窗口的历史评级徽章，以及最新评级（周一评级为准，没有则回退到周五/周末评级）。按 A=+3、B+=+1、B=0、C=-1 计分排序，前三名带金/银/铜皇冠。连续两周 C 会给出一条鼓励性提示。
- **洗净 / 烘干 / 熨烫 / 净水 周承诺**（4 个独立页面）：页面顶部是该模块的里程碑卡片；下方按人展示卡片，每人若干条交付物子卡片——✅/❌ 完成标记（仅负责人/管理员可标，且负责人不能给自己打勾）+ 交付物/验收标准/起止时间/依赖与风险（仅本人可编辑，未锁定前）+ 同款周末/周一评级交互。不同模块之间互相可查看、不能编辑。软件组的个人周承诺表结构和其他模块不一致，暂时跳过（模块里程碑不受影响）。
- **组织管理**（仅管理员）：从飞书通讯录搜索并添加成员，指定其所属模块与角色，或移除成员——这是整个应用权限体系的唯一来源。

## 架构

- **前端**：React + TypeScript + Vite + Tailwind（`web/`），无路由库，页面切换靠本地状态。
- **后端**：Node + Express + TypeScript（`server/`），用飞书官方 `@larksuiteoapi/node-sdk`，以应用身份（tenant_access_token）读写多维表格。
- 生产环境下 Express 直接托管前端构建产物，一个进程、一个 Docker 镜像。
- 身份识别：飞书 JS-SDK 免登录（`tt.requestAuthCode` + OIDC），后端换出自己的 session（httpOnly cookie，JWT 签名，12 小时有效）。
- 本地缓存（`server/src/lib/store.ts`）：每 45 秒从 Bitable 全量同步一次，所有页面读取都走本地缓存，不阻塞在飞书接口上；写入仍然直接落 Bitable。
- 每晚自动把当前缓存内容单向快照进一张独立的备份多维表格（`server/src/lib/nightlyBackup.ts`），管理员也可以手动触发。

## 角色与权限

`roster`（人员名单，通过"组织管理"页面维护，初次启动从 `server/src/roster.json` 引导种入）把每个人的飞书 `open_id` 映射到姓名、所属模块和角色，决定登录后看到什么、能不能打分：

- `admin`：能评所有模块的周末/周一评级；如果同时设置了 `module`，还会额外拥有该模块负责人的能力（填该模块周里程碑、评组内成员、填自己的个人周承诺）。
- `lead`：模块负责人，填本模块周里程碑，评组内成员的个人评级，但不能评自己（自己的评级由 admin 通过给该模块里程碑评分带出）。
- `member`：组员，只能填自己的周承诺。

## 周次编号

团队自己的 "Wxx" 编号比标准 ISO 周数少 1。换算常量 `TEAM_WEEK_OFFSET` 分别写在 `server/src/lib/week.ts` 和 `web/src/lib/week.ts` 里，两处必须保持一致。当前周是持久化状态，只能由管理员在"组织管理"页面显式"进入下一周"推进，不会自动跳变。如果团队的编号规则以后变了（比如跨年），记得回来改这两个文件。

## 本地开发

```bash
npm install

# 终端 1：后端（读 server/.env）
npm run dev:server

# 终端 2：前端
npm run dev:web
```

打开 http://localhost:5173。因为不在飞书客户端里，免登录走不通，会自动弹出一个"本地开发模式"身份选择器（`server/src/routes/auth.ts` 里的 `/api/auth/dev-login`，仅在 `NODE_ENV !== production` 时启用），选一个人登录即可测试全部功能，这个入口在生产环境不会启用。

**改了 `server/.env` 之后要重启后端进程**——`dotenv` 只在启动时读一次，`tsx watch` 的热重载不会重新加载环境变量。

## 生产构建 / 部署

```bash
docker build -t premir-weekly-commit .
docker run -p 3000:3000 --env-file server/.env.production premir-weekly-commit
```

或者不用 Docker：`npm run build && npm start`（`start` 会跑 `server/dist/index.js`，同时托管 `web/dist`）。

部署上线后，去飞书开发者后台给这个自建应用配置"主页"（工作台入口 / 侧边栏入口），URL 填部署后的地址，团队成员就能在飞书里直接点开用。

## 环境变量

见 `server/.env.example`。关键几项：

| 变量 | 说明 |
| --- | --- |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 自建应用凭证 |
| `SESSION_SECRET` | 任意长随机字符串，签 session JWT 用 |
| `BASE_TOKEN` | 多维表格的 app_token |
| `TABLE_ID_*` | 各表的 table_id，`lark-cli base +table-list --base-token <BASE_TOKEN>` 可查 |

应用需要以应用身份（tenant_access_token）被加为目标多维表格的编辑协作者，权限入口：`https://open.feishu.cn/app/<App ID>/auth?q=bitable:app,bitable:app:readonly,base:record:retrieve`。如果目标表格开启了"高级权限"（字段/记录级精细权限），需要关闭或在规则里显式放行这个应用，否则写入会被拒绝（`Permission denied`，code 1254302）。

## 已知限制

- 软件组的"周承诺"表结构和其他 4 个模块不一致（用的是 A/B/B+ 三个独立字段，而不是通用的"验收标准"字段），个人周承诺功能暂时跳过软件组，模块里程碑不受影响。
