# PREMIR 周承诺

飞书自建应用主页：把"模块周里程碑 + 个人周承诺 + 全员评级"这套流程从多维表格的原始表格界面，封装成卡片式表单，嵌在飞书客户端里免登录使用，桌面宽屏布局（左侧导航 + 右上角周次切换）。

底层数据仍然是你现有的那个多维表格（模块周里程碑 + 全员评级表 + 5 张模块周承诺表），这个应用只是读写它，不新建表。

评级徽章统一用"币"的视觉（金=A、橙=B+、淡蓝=B、红=C），不是文字方块；哪里出现评级，哪里就是这套配色。

左侧六个页面：
- **各模块周里程碑**：4 个结构模块（不含软件组，见下）并排卡片，全内容直接展示，不需要点开。卡头是主色实心方块（模块名 + 负责人真实飞书头像/姓名，白字反白），积分最高的模块左上角插一个金色皇冠、右侧配一个同高的"全场最佳"金色方块。卡身：里程碑描述/B验收标准/B+验收标准可编辑（负责人/CEO），验收标准若写成"1.xxx 2.yyy"编号格式会自动拆成独立行，每行前面一个 ✅/❌/— 下拉（CEO 可标）；负责人历史评级军功章（绶带+币两段式，历史范围固定在真实当前周，不随你切换查看的周变化，点击可跳转）；底部"周末评级"/"周一评级"两档独立评分——选等级→填备注（选填）→点"确认提交"才真正锁死，前后端都强制不可二次修改。
- **全员评级表**：每人一张统一大小的卡片，纯展示、不可编辑。上部头像+姓名；中部完整历史军功章（固定 8 周窗口，人人一样长）；下部放大展示"最新评级"（周一评级为准，没有则退回周五评级）。按 A+3/B+ +1/B+0/C-1 算分排序，前三名头像左上角插金/银/铜皇冠（SVG 渐变，非 emoji）。连续 2 周 C 有一条鼓励性提示（不含负面措辞）。
- **洗净/烘干/熨烫/净水 周承诺**（4 个独立页面）：页面顶部是这个模块的里程碑卡片（跟"各模块周里程碑"同一个组件，只是单张、不带排名）；下方按人横排卡片（负责人在内，人人同款）——卡头同款主色方块+头像；卡身是若干条"交付物子卡片"，每条前面一个 ✅/❌ 复选框（仅负责人/CEO 可标）+ 交付物/验收标准/起止时间/依赖与风险（仅本人可编辑，未锁定前）+ 底部周末/周一评级（选项→备注→确认提交→锁定，同款交互）。**负责人不能给自己的卡片打分/打勾**——那是 CEO 的权限，跟模块级评分同一个道理，前后端都强制了这条规则。不同模块互相可查看，不能编辑别组内容。软件组的个人周承诺表结构跟其他模块不一致，暂时跳过（模块里程碑不受影响）。

## 架构

- **前端**：React + TypeScript + Vite + Tailwind（`web/`）
- **后端**：Node + Express + TypeScript（`server/`），用飞书官方 `@larksuiteoapi/node-sdk`，以应用身份（tenant_access_token）读写多维表格
- 生产环境下 Express 直接托管前端构建产物，一个进程、一个 Docker 镜像
- 身份识别：飞书 JS-SDK 免登录（`tt.requestAuthCode`），后端换出自己的 session（httpOnly cookie，JWT 签名）

## 周次编号

团队自己的"Wxx"编号比标准 ISO 周数少 1（已用 2026-07-27 = 团队 W30 = ISO 第 31 周核实）。换算写在 `server/src/lib/week.ts` 和 `web/src/lib/week.ts` 的 `TEAM_WEEK_OFFSET` 常量里，两处要保持一致。如果团队的编号规则以后变了（比如跨年），记得回来改这两个文件。

## 上线前要做的事（生产表格）

### 1. 应用身份权限 ✅ 已开通，全局生效，生产表格不用重复做

用应用自己的身份（tenant_access_token）读写多维表格，需要在开发者后台单独开通权限——这和个人账号 `lark-cli auth login` 拿到的 OAuth 授权是两回事。入口：`https://open.feishu.cn/app/<App ID>/auth?q=bitable:app,bitable:app:readonly,base:record:retrieve`。

### 2. 把应用加为生产表格的协作者

```bash
lark-cli drive +member-add --token <生产 base_token> --type bitable \
  --member-id <App ID> --member-type appid --perm edit --yes
```

### 3. 检查生产表格是否开了"高级权限"

测试副本从生产表格复制过来时带上了"高级权限"（字段/记录级精细权限），导致即使应用已经是编辑协作者，写入还是被拒绝（`Permission denied`，code 1254302）。测试副本上关掉了（`lark-cli base +advperm-disable`）。生产表格如果也开着，上线前要么关掉，要么在高级权限规则里显式放行这个应用。

### 4. 在生产表格上补齐这些字段（源表格全程没碰过）

- "模块周里程碑"表：把"模块评级"改名"周末评级"，新增"周一评级"（select，选项同周末评级：A/B+/B/C/待评），新增"B达标""B+达标"（**text 类型**，不是 select——存的是"✅,·,❌"这种按条对齐的编码，不是单个值）
- 5 张"周承诺"表的"个人评级"字段补上 B+ 选项（目前只有 A/B/C/待评）

具体命令参考本仓库开发过程中对测试副本的操作（`lark-cli base +field-update` / `+field-create`）。

### 5. 软件组的"周承诺"表结构对不上

其他 4 个模块的周承诺表都用一个通用的"验收标准"字段；软件组那张表用的是 A/B/B+ 三个独立字段（跟里程碑表结构一样，可能是当初建错了模板）。这个应用暂时**跳过了软件组的个人周承诺功能**（模块里程碑不受影响，正常可用）。等你决定好怎么对齐这张表，告诉我，我再补上。

## 人员名单（roster）

`server/src/roster.json` 维护"open_id → 姓名/模块/角色"的映射，决定登录后看到什么卡片、能不能打分。角色：

- `admin`：CEO/COO，能评所有模块的"周末评级/周一评级"；如果 admin 同时设置了 `module`，还会额外拥有该模块负责人的能力（填该模块周里程碑、评该模块组员、填自己的个人周承诺）——目前用在陈曦斌兼任软件组负责人这个场景
- `lead`：模块负责人，填本模块的周里程碑，评组内成员的"个人评级"
- `member`：组员，只能填自己的周承诺

新增/离职人员、模块负责人变更，都是直接改这个文件。

## 本地开发

```bash
npm install

# 终端 1：后端（默认读 server/.env，指向上面那个干净的测试副本）
npm run dev:server

# 终端 2：前端
npm run dev:web
```

打开 http://localhost:5173 。因为不在飞书客户端里，免登录走不通，会自动弹出一个"本地开发模式"身份选择器（`server/src/routes/auth.ts` 里的 `/api/auth/dev-login`，仅在 `NODE_ENV !== production` 时启用），选一个人登录即可测试全部功能。

生产环境的部署不会启用这个入口。

**改了 `server/.env` 之后要重启后端进程**——`dotenv` 只在启动时读一次，`tsx watch` 的热重载不会重新加载环境变量。

## 生产构建 / 部署

```bash
docker build -t premir-weekly-commit .
docker run -p 3000:3000 --env-file server/.env.production premir-weekly-commit
```

或者不用 Docker：`npm run build && npm start`（`start` 会跑 `server/dist/index.js`，同时托管 `web/dist`）。

部署上线后，去飞书开发者后台给这个自建应用配置"主页"（工作台入口 / 侧边栏入口），URL 填你部署后的地址，团队成员就能在飞书里直接点开用了。

## 环境变量

见 `server/.env.example`。关键几项：

| 变量 | 说明 |
| --- | --- |
| `FEISHU_APP_ID` / `FEISHU_APP_SECRET` | 自建应用凭证 |
| `SESSION_SECRET` | 任意长随机字符串，签 session JWT 用 |
| `BASE_TOKEN` | 多维表格的 app_token（先用测试副本，上线前切换成生产表格） |
| `TABLE_ID_*` | 各表的 table_id，`lark-cli base +table-list --base-token <BASE_TOKEN>` 可查 |

切换到生产表格时，把这些值换成生产 base 的对应 ID 就行，代码不用改。
